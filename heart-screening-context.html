01Overview and positioning

A mobile app that records heart sounds through a phone mic (or a ₹500 stethoscope + collar-mic attachment), checks recording quality, and uses AI to classify the heartbeat as Normal, Needs check-up or Recording unclear. Gemini explains the result in plain Hindi and English. The user can share the result with a doctor.

Rule #1: This is a screening tool, not a diagnosis. Never use the words "diagnose", "detects disease" or "you have X" in UI, API messages, prompts or the pitch. Say "screening", "pre-check", "may need a check-up".
  • Working name: not final. Shortlist: HridAI (recommended), Dhadkan, Spandan, LubDub. The submitted deck currently says "HeartSense". Repo code-name: heartscreen.
  • Problem: Heart disease is the leading cause of death in India. Rural areas have very few cardiologists, and AI digital stethoscopes cost ₹20,000+.
  • Target users: ASHA workers, PHCs and rural clinics running screening camps, families monitoring high-risk patients, doctors doing telemedicine.
  • Hackathon rule that matters: Using Google / Google Cloud tech and AI earns bonus marks. That is why we use Gemini, Firebase, Cloud Run and Vertex AI.
  • Competitor reference: Eko (US) has FDA-cleared murmur detection (87% sensitivity / 87% specificity) on its own digital stethoscope. Our angle: affordable, phone-first, Indian languages.

03Scope: MVP vs stretch

MVP (must ship for demo)

  • Consent + patient info form (age, sex, height, weight)
  • Guided recording at 2 chest locations (mitral + aortic), 15 s each
  • Server-side quality check with "re-record" feedback
  • Classification: Normal / Needs check-up / Recording unclear + confidence
  • Heart rate (bpm)
  • Gemini explanation in Hindi + English
  • Result screen with disclaimer; history list
  • Deployed backend on Cloud Run

Stretch (only if MVP is done)

  • All 4 chest locations
  • Grad-CAM heatmap image on result screen
  • Upload old reports (image/PDF) → Gemini summary shown with result
  • Share result as PDF / link with doctor
  • Waveform playback with S1/S2 markers

Out of scope

  • Murmur type classification, ECG, on-device/offline model, doctor dashboard, clinical validation. These go in the "future scope" slide only.

04Architecture

flowchart TD
  A[RN app: consent + patient info] --> B[RN app: guided recording per chest spot]
  B -->|multipart upload| C[FastAPI on Cloud Run]
  C --> D{Quality check}
  D -->|rejected| B
  D -->|accepted| E[DSP preprocess: resample, bandpass, normalize]
  E --> F[5 s windows to log-mel spectrograms]
  F --> G[Audio model: fine-tuned CardioPHON / CNN]
  A -.patient data.-> H
  G --> H[Fusion: audio score + age, sex, height, weight]
  H --> I[Result: normal / needs check-up / unclear]
  I --> J[Gemini: explanation in Hindi + English]
  J --> K[RN app: result screen, share, history]
  C <--> L[(Firestore + Cloud Storage)]

Key design decisions

  • No AI "enhancement" of audio. Denoising models can erase murmurs (murmurs look like noise) or invent beats. We use classical DSP only, and reject bad audio instead of fixing it.
  • Same preprocessing in training and inference. One shared Python module (audio.py) is imported by both the training code and the API.
  • Gemini never classifies. It only explains a result that our model already produced, and summarizes uploaded reports.
  • Backend owns all writes to Firestore and Storage. The app only talks to our API (simpler security rules).
  • Synchronous analyze call (a few seconds). No queues or workers for the hackathon.

07Recording spec (frontend)

  • Format: record with expo-audio high-quality preset: m4a / AAC, mono, 44.1 kHz. Android cannot record WAV natively, so we keep m4a on both platforms. Backend converts with ffmpeg.
  • Duration: target 15 s, hard minimum 8 s, max 30 s. Auto-stop at 15 s.
  • File size limit: 5 MB per recording.
  • Locations (same codes as the CirCor dataset):
    CodeNameWhere on chest
    MVMitralLeft side, 5th rib space, below the nipple line (apex)
    AVAorticRight of breastbone, 2nd rib space
    PVPulmonicLeft of breastbone, 2nd rib space
    TVTricuspidLeft lower edge of breastbone, 4th–5th rib space
  • Source field: phone_mic or stethoscope_mic (user picks once on the placement screen).
  • User instructions (show as 4 short tips with icons): sit still and breathe normally · switch off fan/AC/TV · press the phone's bottom (mic side) firmly on bare skin · don't talk during recording.
  • Ask mic permission on screen 4, not at app launch. Handle "denied" with a settings link.

08API contract (v1)

Conventions

  • Base URL: EXPO_PUBLIC_API_BASE_URL (Cloud Run URL), all routes under /v1.
  • Auth header on every call except /healthz: Authorization: Bearer <Firebase ID token>. Backend verifies with firebase_admin.auth.verify_id_token. Users only see their own screenings.
  • JSON keys in snake_case. Timestamps ISO 8601 UTC. IDs are strings.
  • Language: "en" or "hi". User-facing messages are returned in both (message_en, message_hi).
  • Mock mode: backend env MOCK_INFERENCE=true returns fixed realistic results, so the app can be built before the model is ready.

10Audio pipeline (backend)

One module, backend/app/services/audio.py, used by both the API and the training code. All numbers below are starting values; whatever is used in training must be used in inference. They live in one config object.

StepWhatStarting value
1. Decodeffmpeg → mono float32 PCMffmpeg -i in.m4a -ac 1 -f wav
2. TrimDrop first and last 1 s (handling noise when placing/removing phone)1.0 s each side
3. ResampleTo one target rate for all dataTARGET_SR = 2000 Hz (PhysioNet 2016 is 2 kHz, CirCor is 4 kHz). Use the pretrained model's rate if it needs a different one.
4. BandpassButterworth, zero-phase (scipy.signal.butter + sosfiltfilt)Order 4, 25–400 Hz
5. Spike removalRemove friction spikes (Schmidt et al. method)Optional
6. NormalizeScale amplitudeDivide by max abs value (peak normalize)
7. Quality checkSee belowReject → accepted: false
8. SegmentFixed windows5 s windows, 2.5 s hop; drop the last partial window
9. FeaturesLog-mel spectrogram per windown_fft=256, hop_length=40 (20 ms), n_mels=64, fmin=20, fmax=800; then log(1e-6 + S) and per-window standardization

Quality check rules (all must pass)

  • Duration ≥ 8 s after trim → else too_short
  • Clipping: share of raw samples with |x| ≥ 0.99 is under 1% → else clipping
  • Level: RMS of filtered signal above floor (tune on real phone recordings) → else too_quiet
  • Noise ratio: energy in 25–400 Hz ÷ total energy above threshold → else too_noisy
  • Heartbeat present: build an envelope (Hilbert or homomorphic), autocorrelate, find peak in the 40–180 bpm lag range. Weak peak → no_heartbeat_detected; rate outside range → heart_rate_out_of_range. This also gives heart_rate_bpm.
  • If the CardioPHON quality head is usable, combine its score into quality.score.

Tune thresholds on: dataset recordings marked good, dataset recordings marked unclear, and ~20 team phone recordings (quiet room vs fan on vs talking).

11ML model and training

Datasets

DatasetWhat it givesWatch out for
PhysioNet / CinC 2016Normal vs abnormal heart sounds, several sources, 2 kHzLittle demographic data; mixed recording devices
CirCor DigiScope 20221,568 patients, 5,282 recordings from 4 locations, 4 kHz. Murmur Present / Absent / Unknown, detailed murmur labels, S1/S2 segmentation, age group, sex, height, weightPediatric (0–21 years, Brazil). Imbalanced: about 74% murmur absent, 19% present, 7% unknown. Check which split is publicly released.

Labels

  • Binary target abnormal: PhysioNet 2016 abnormal = 1, normal = 0. CirCor murmur Present = 1, Absent = 0.
  • CirCor Unknown: exclude from classifier training; use as negative examples for the quality check.

Splits (critical)

  • Split by patient, never by recording or window. Same patient in train and test gives fake high accuracy.
  • 70 / 15 / 15 train / val / test, stratified by label and dataset. Fix the random seed and save patient ID lists in ml/splits/.

Model plan

  1. Baseline first (day 1): small CNN on log-mel windows. Proves the pipeline end to end.
  2. Main model: fine-tune pretrained CardioPHON (self-supervised on 6 heart sound datasets, includes quality assessment). If weights or code are hard to use in time, fine-tune a general pretrained audio CNN instead.
  3. Window → recording: mean of window probabilities.
  4. Recording → screening: max over locations (favours sensitivity: one bad spot flags the screening).
  5. Metadata fusion (late fusion): logistic regression or small MLP on [audio_probability, age_years, sex, height_cm, weight_kg, bmi, missing flags]. Map CirCor age groups to midpoint years. Fill missing values with training medians + a missing flag. Report results with and without metadata.

Training details

  • Imbalance: class-weighted loss (or focal loss) + oversampling of abnormal windows.
  • Augmentation: random time shift, gain ±6 dB, added background noise at 10–30 dB SNR, small time-stretch (±5%).
  • Early stopping on validation AUC.
  • Export: TorchScript (model.pt) for CPU inference. Version string like cardiophon-ft-0.1.
  • Explainability (stretch): Grad-CAM on last conv layer, overlay on spectrogram, save PNG.

Metrics to report (on test split)

  • Sensitivity, specificity, AUC, F1, confusion matrix, per dataset and combined.
  • Choose decision threshold on validation for sensitivity ≥ 0.85. Missing a sick heart is worse than a false alarm.
  • Log every run in ml/results.md: date, data, params, metrics.

Known limitations (say these in the pitch)

  • CirCor is pediatric; adult performance is unproven.
  • Training data is stethoscope audio; phone mic audio is different (domain gap).
  • No clinical validation yet.

12Gemini usage

  • Two jobs only: (1) explain the model result in plain Hindi and English, (2) summarize uploaded reports (multimodal input: image/PDF).
  • Model: a current Gemini Flash-class model. Pin the exact ID in GEMINI_MODEL.
  • Temperature 0.2. Request JSON output. Timeout 15 s.
  • Fallback: if Gemini fails or times out, use fixed template text per label. The result must never depend on Gemini.
  • Do not send names or any identifiers to Gemini. Only age, sex, label, probabilities, bpm, locations, report summary.

Explanation prompt (starting version)

SYSTEM:
You explain the output of a heart sound SCREENING tool to a non-medical person in India.
Rules:
- This is not a diagnosis. Never name a disease as certain. Never say "you have".
- Use simple words. Max 3 short sentences per language.
- If label is "needs_checkup": calmly recommend seeing a doctor soon. Do not cause panic.

16Privacy, safety, legal

  • Consent screen before any data is collected. Store consent version + timestamp.
  • Collect the minimum: no name, phone, address or exact date of birth.
  • Users can delete a screening (all audio and reports).
  • Follow the spirit of India's Digital Personal Data Protection Act, 2023: clear purpose, consent, deletion on request.
  • Delete all hackathon data after the event unless the team decides otherwise.
  • Team test recordings: only from people who agreed, and never used to claim accuracy.
  • Wording: "screening", "pre-check", "may need a check-up". Never "diagnosis".

Consent text (draft, EN): "This app records your heartbeat and uses AI to check if it sounds normal. It is a screening tool and does not replace a doctor. Your recordings and basic details (age, sex, height, weight) are stored securely to give you a result. We do not collect your name or phone number. You can delete your data at any time."

20Glossary

TermMeaning
S1 / S2The two main heart sounds ("lub" and "dub"): valves closing at the start of systole and diastole.
Systole / diastoleHeart contracting / heart relaxing. Murmurs are described by which phase they occur in.
MurmurExtra whooshing sound from turbulent blood flow. Can be harmless or a sign of valve disease.
AuscultationListening to body sounds, usually with a stethoscope.
PCGPhonocardiogram: a recording of heart sounds.
Bandpass filterKeeps frequencies in a range (here 25–400 Hz) and removes the rest.
Mel-spectrogramA picture of sound: time on x, pitch on y, loudness as colour. The CNN reads this like an image.
SensitivityOf all truly abnormal cases, the share we flag. Our priority.
SpecificityOf all truly normal cases, the share we correctly call normal.
AUCHow well the model ranks abnormal above normal across all thresholds (0.5 = random, 1 = perfect).
Grad-CAMHeatmap showing which part of the spectrogram drove the model's decision.
Late fusionCombining the audio model's output with patient data in a second small model.
ASHA workerAccredited Social Health Activist: community health worker in India.
PHCPrimary Health Centre.
